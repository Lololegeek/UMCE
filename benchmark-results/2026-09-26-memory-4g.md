# UMCE 1.21.1 constrained-heap snapshot

Captured 2026-09-26 with Minecraft 1.21.1, Fabric Loader 0.16.14, Fabric API
0.116.17+1.21.1, and Java 21. Both runs used the same stress harness and fixed
seed, with 100 connected protocol clients, 10,000 requested entities, and 500
villagers, 256 filled hoppers, paired observers, a force-loaded 16 x 16 chunk
area, and clients exploring new chunks. No Create factory is included because
the tested adapter is Fabric and the available Create build targets NeoForge.
Each condition warmed up and ran the workload for 60 seconds before the JVM
class histogram requested a full GC. The heap snapshot pauses the server and
is diagnostic, not a tick-performance measurement.

## Heap capped at 4 GiB

Both servers used `-Xms1G -Xmx4G`. One baseline run and one UMCE run completed
without an out-of-memory error.

| Measurement after class histogram | Baseline | With UMCE |
|---|---:|---:|
| Process working set | 1,539.2 MiB | 1,527.4 MiB |
| G1 heap committed | 1,024 MiB | 1,024 MiB |
| G1 heap used | 933.5 MiB | 926.2 MiB |
| Live histogram total | 401.1 MiB | 484.1 MiB |
| `PathNode` objects (`net.minecraft.class_9`) | 283,499 / 17.3 MiB | 582,509 / 35.6 MiB |

These are single snapshots. Player exploration and pathfinding vary between
runs; the live histogram is larger with UMCE here, so this does not establish
a RAM reduction from the mod. A path-node table trimming experiment ran only
four times during a separate one-minute sample and was removed because it did
not demonstrate a memory gain. The UMCE measurements in the table use the
rebuilt final JAR without that experiment.

## Effect of the benchmark heap settings

The earlier baseline run with the harness defaults `-Xms8G -Xmx8G` reported a
6,328.5 MiB working set after histogram and 8,192 MiB of committed G1 heap.
With `-Xms1G -Xmx4G`, the later baseline run reported 1,539.2 MiB and 1,024 MiB
committed. These runs show why a fixed 8 GiB initial heap is unsuitable when
measuring small-memory hosts. The settings affect the JVM and are not a UMCE
optimization; the 4 GiB cap is the tested configuration for this workload.

Raw local histograms are excluded from Git (`*-heap.txt`) because each is over
1 MiB. Recreate them with:

```powershell
./tools/benchmark-fabric-stress-1.21.1.ps1 -HeapSnapshotOnly -SnapshotCondition baseline -ResultTag 4g -InitialHeap 1G -MaximumHeap 4G -Players 100 -Entities 10000 -Villagers 500 -MeasureSeconds 60
```
