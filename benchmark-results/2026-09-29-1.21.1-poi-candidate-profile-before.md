# UMCE Fabric 1.21.1 POI candidate collection profile

Captured: 2026-09-29 UTC, before this patch. Source artifact: [mixed Spark profile](2026-09-29-1.21.1-ai-profile-mix-2000-pigs-500-villagers.sparkprofile). Spark used its Java sampling engine on Windows; figures are inclusive sample weights, not timings or allocations.

## Workload and attribution

The capture used 2,000 pigs and 500 villagers, no gameplay patch, 10 s warm-up, and 30 s sampling. The profile contains 30,096 samples under the server thread.

A call-tree extraction from that saved profile found this villager Brain path:

```text
VillagerEntity.tick / mobTick
  MobEntity.tickNewAi
    Brain.tick
      Brain.startTasks
        SingleTickTask.tick
          TaskTriggerer
            FindPointOfInterestTask.method_46885
              Stream.collect
                AbstractPipeline.evaluate
                  StreamSpliterators.fillBuffer / doAdvance
```

The inclusive node for `FindPointOfInterestTask.method_46885` had 1,920 samples in this tree; the associated `AbstractPipeline.evaluate` node had 1,920, and `WrappingSpliterator` nodes had 1,732. These overlapping values must not be added.

Minecraft 1.21.1 bytecode for this path creates a POI stream, applies `limit(5)`, then calls `collect(Collectors.toSet())` before path selection. The tested candidate keeps the stream, limit, collector supplier/accumulator/finisher, sequential encounter order, and all POI/pathfinding work. It only replaces the sequential terminal reduction with direct iterator accumulation. Parallel streams fall back to the vanilla `collect` call.

## Limits

The profile proves that this code path runs in the villager workload; it does not prove the terminal loop is faster. This candidate is manual-only and OFF by default. The next check is a short baseline / passive UMCE / patch ablation with identical saved worlds. Reject it if MSPT, tail latency, CPU, or POI outcomes worsen.
