# Entity hot-path profile before the first gameplay patch

Captured before modifying adapter/runtime code on Minecraft 1.21.1, Fabric Loader 0.16.14, Java 21, with Spark 1.10.109's built-in Java sampler. The UMCE tick profiler was disabled. The sample window was 60 seconds after the normal 20-second server warmup.

## Isolated entity workload

- 0 protocol clients, 10,114 total entities in Spark's captured world metadata (approximately 10k saved pigs plus naturally present entities), 0 villagers, 0 configured hopper rows, 0 redstone clocks, 0 TNT.
- The server completed 597 ticks during the 60-second capture, so this workload was heavily tick-limited.
- Raw profile: [2026-09-27-1.21.1-entity-only-before.sparkprofile](2026-09-27-1.21.1-entity-only-before.sparkprofile).

Largest inclusive server-thread stack weights (Spark weighted samples; child work is included, so these are not exclusive method costs):

| Stack node | Weight | Share of 60,188 sampled units |
|---|---:|---:|
| `EntityList.forEach` | 57,644 | 95.8% |
| `MobEntity.tick` | 56,588 | 94.0% |
| `SectionedEntityCache.forEachIntersects` | 14,648 | 24.3% |
| `SectionedEntityCache.forEachInBox` | 14,640 | 24.3% |

The `EntityList.forEach` figure includes nearly the whole entity tick called inside it; it does not mean the iteration method itself consumes 95.8% of CPU. The spatial-query path is a better isolated candidate: it is reached from entity AI and appears repeatedly in this workload. Vanilla already stores entities in section-indexed collections, so the proposed patch will target the cost of probing a small query box within that existing index, without maintaining a second index.

## Hopper candidate check

A separate profile used 256 configured hoppers, no players, no configured entities, no villagers, no clocks, and no TNT. `HopperBlockEntity.serverTick` contributed 364 inclusive sampled units (about 0.6% of the server-thread sample weight), so hoppers are not the first patch target for this workload.

Raw profile: [2026-09-27-1.21.1-hoppers-only-before.sparkprofile](2026-09-27-1.21.1-hoppers-only-before.sparkprofile).

## Candidate

Test one opt-in `SectionedEntityCache` small-box lookup path. The vanilla path scans the sorted set of existing section positions in the query's X range, filters Y/Z bounds, then looks up each matching section. The candidate path will directly probe packed section positions only for small query volumes and fall back to vanilla for larger boxes. It must preserve packed-coordinate visitation order and be disabled by default; SAFE mode will continue through the original vanilla method.

This is a hypothesis selected from the pre-change profile, not a claimed improvement. The patch will be retained only if the three-way benchmarks show a repeatable gain without a material RAM or behavior change.
