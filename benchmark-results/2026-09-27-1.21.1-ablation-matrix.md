# UMCE 1.21.1 ablation matrix

## What this matrix can test

The current Fabric 1.21.1 adapter contains no collision, entity, worldgen, chunk I/O, or network optimization patch. The only per-tick operation in UMCE was its diagnostics profiler: two tick event callbacks, `System.nanoTime()` reads, and a synchronized sample write. `PatchEngine` is not connected to a production patch. Therefore, the requested gameplay-patch ablations are not available in this checkout; the valid ablation is the profiler enabled versus disabled.

Profiling is now disabled by default. It can be enabled for diagnostics with `-Dumce.tickProfiler.enabled=true`. The benchmark scripts accept `-EnableTickProfiler` and apply the property only to the UMCE server.

## Paired MSPT results

Each entry is the median paired percentage change in rolling MSPT windows for UMCE versus the no-UMCE baseline. Positive means slower with UMCE. `SD` is the sample standard deviation of the paired changes; there are only two valid pairs per condition, so these results are descriptive and cannot establish small effects as significant.

| Workload | Earlier reported delta | Profiler off | SD off | Profiler on | SD on |
|---|---:|---:|---:|---:|---:|
| 10k entities | +3.27% | −0.80% | 0.57 pp | −3.23% | 6.39 pp |
| Collisions, 10k entities + 50 players | +9.76% | +2.55% | 1.84 pp | +2.77% | 10.80 pp |
| Worldgen, 20 players | +6.92% | −11.05% | 2.82 pp | −0.04% | 4.10 pp |
| Chunk I/O | +4.55% | +1.39% | 3.76 pp | +7.14% | 10.10 pp |
| Network, 100 clients | −5.76% | +5.40% | 4.49 pp | −10.62% | 10.82 pp |
| AI-heavy | −5.41% | −1.01% | 0.01 pp | +1.26% | 5.31 pp |
| Mixed | −2.01% | +14.19% | 62.84 pp | +9.04% | 39.12 pp |
| 10k TNT | −5.81% | −7.89% | 11.16 pp | −5.90% | 0.49 pp |

These runs do not reproduce the earlier large entity, collision, or worldgen regressions as a stable effect of the current code. Chunk I/O remains mildly positive with profiling off, but its two-pair spread is larger than that delta. The mixed workload and 100-client network case vary sharply between profiler states and pairs. The repository has no gameplay optimization to explain or preserve the earlier gains; those gains are not attributable to UMCE patches in this revision.

| Without entity patch | No patch exists | Same gameplay code as UMCE complete. |

| Without chunk I/O patch | No patch exists | Same gameplay code as UMCE complete. |
| Without network patch | No patch exists | Same gameplay code as UMCE complete. |
| Tick profiler enabled / disabled | Yes | The only real ablation performed; profiling is opt-in and disabled by default. |

No locks, spatial indexes, worldgen caches, async queues, or patch-specific allocations exist in this adapter to investigate. The synchronized operation belongs to `TickProfiler.recordTick()` and runs only when the diagnostic profiler is enabled.

## Method and limitations

Each scenario used two paired runs, 20 seconds of warmup and a 30-second measured interval per server condition, alternating which condition ran first. Baseline and UMCE in each pair used copies of the same prepared world and the same client workload. Profiler-on and profiler-off matrices prepared their worlds independently. Network cases verified 100 online clients; the mixed case also reached 100. The TNT case reports rolling tick percentiles separately because explosion ticks create large tails.

Two pairs are not enough to prove the target of zero significant regressions. In particular, mixed, network, collision, chunk I/O, and TNT have visible run-to-run spread. A follow-up aimed at statistical confidence should increase repeats to at least five and keep the host otherwise idle. The present evidence supports disabling the profiler by default and does not justify introducing or retaining any gameplay patch.

Per-scenario Markdown reports and raw CSV files are alongside this report, with `profiler-off` or `profiler-on` in their filenames. The profiler-off summary covers all eight scenarios. The profiler-on summary covers the five scenarios rerun after the first long matrix was interrupted; its per-scenario reports, combined here, cover all eight workloads.
